# The Quality Bar

Scope is governed by this file, not by a deadline. A project is done when an
adversarial staff-level review returns PASS on all ten points below. Not when it
feels finished, and not when it is perfect.

The companion rule is Smallest-Excellent-Design: excellence is depth,
correctness, and evidence on a tight scope, never feature count. Before adding
anything, ask whether it moves a point below from WEAK to PASS. If it does not,
it belongs on the Depth Ladder in BACKLOG.md, not in the current milestone.

## The ten points

1. **Works from zero.** Fresh clone, documented setup, running in five minutes
   or one command. The live demo works from a cold browser, on a phone, today.

2. **Correct under failure.** Every external call has timeouts, retries, and
   backoff. Error paths are tested, not merely written. At least one
   fault-injection test per external dependency. Graceful degradation is
   demonstrated, not claimed.

3. **Measured, honestly.** Every headline claim has a benchmark with a
   methodology section: number of runs, variance, model or hardware plus the
   date, and a reproduction script in the repo. Limitations stated plainly. If a
   number in the README cannot be regenerated by a script, it does not go in the
   README.

4. **Eval-gated.** A ShipGate suite exists for the project's core behavior, CI
   blocks regressions, and judge calibration against hand labels is reported
   wherever an LLM judges.

5. **Observable.** Spanlight-traced end to end, at least one dashboard, and at
   least one alert that has actually fired during testing. Screenshot it.

6. **Secure by default.** No secrets in code or history. Inputs validated at
   boundaries. Least-privilege tool access. Anything touching untrusted input
   carries a short threat-model section in the README.

7. **Code a staff engineer would sign.** Typed, linted, behaviorally tested with
   a test per acceptance criterion, small modules, no dead code, and a commit
   history that tells a story rather than forty commits saying "wip".

8. **Documented like a real product.** README covers Problem, Architecture with
   a diagram that matches reality, Benchmarks, Technical Decisions, What Broke,
   and a Runbook. DECISIONS.md holds genuine tradeoffs with the alternatives that
   were considered.

9. **A contribution, not a copy.** The Depth Chapter: at least one artifact that
   exists nowhere else, such as an open dataset, a published ablation or study,
   novel test scenarios, or a field report with real numbers. This point is what
   separates doing the tutorial well from doing original work.

10. **Communicated.** A demo video with the money moment inside thirty seconds,
    and a deep-dive write-up in the author's own voice. A stranger gets the
    value in sixty seconds and the depth in ten minutes.

## How this file is used

Every repo in the portfolio inherits this file unchanged. Backlog tasks are
tagged with the point or points they serve, and a task serving no point does not
belong in the backlog. Hardening and Measurement milestones carry as many tasks
as Core, because points 2, 3, and 5 are where the bar actually bites.
